# Schema-aware editor completion

This reference precedes the implementation of PRD §5.3 table, column, schema and keyword completion. It uses the navigator's accepted metadata snapshots, preserving §5.2's rule that children load only when a node is expanded. Typing never submits a database request.

After two identifier characters, the editor presents a bounded completion list. Ctrl+Space explicitly opens the list, including an empty prefix. SQL keywords are available while disconnected. With an active connection, schemas, tables/views and columns already loaded in its navigator appear alongside keywords. Expanding or refreshing navigator nodes updates the available names; switching connections immediately changes the catalog and dismisses an old popup. Disconnect removes that connection's names. Completion never connects a restored tab or executes SQL.

Suggestions carry a display label, insertion text and kind in shared contracts. Metadata insertion uses driver-provided quoted qualified names rather than constructing SQL from raw labels. Unqualified prefixes match object labels. A qualified prefix matches the quoted/unquoted schema/table path and filters the appropriate descendants; accepting it replaces the complete qualified prefix without duplicating it. Keywords insert their standard spelling. Acceptance is one undoable text edit. Escape dismisses the popup. Comments and string literals must not trigger schema suggestions.

The metadata model publishes only accepted request generations. Refresh invalidates the refreshed subtree immediately, and late replies cannot repopulate it. Catalogs remain isolated by connection. UI completion evaluates a bounded local snapshot; no asynchronous lexer preparation or database work runs on the UI thread. Limits are shared and explicit: 100 visible results, 256 UTF-8 bytes for the typed prefix, 10,000 cached metadata entries and 8 MiB metadata text per connection. Oversized metadata is omitted from completion without affecting the navigator; the UI explains when the catalog is partial.

Acceptance covers disconnected keywords, schemas/tables/views/columns, quoted and Unicode identifiers, qualification, correct insertion and undo, active-connection isolation, refresh/disconnect invalidation, stale metadata, request-free typing, cache/result limits, and editor destruction during completion. Advanced SQL scope/alias inference is outside this basic completion slice; it must not be advertised as implemented.

Native implementation reference: [workspace](native-completion.png) and [completion popup](native-completion-popup.png). The popup is a separate native window, so the two captures are recorded separately. Duplicate labels display their qualified paths. Control+Space (physical Control on macOS) opens completion from Edit → Complete SQL. This binding is reserved in the preferences conflict catalog. A single worker scans immutable SQL/catalog snapshots; generation, revision, cursor and selection checks prevent stale suggestions from reappearing.
