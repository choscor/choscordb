# Saved connection profiles

This nonmodal dialog follows the native spacing, palette, keyboard focus, and plain-text error rules in [README.md](README.md). A saved-profile list occupies the left column; the right column contains a labeled connection form. New creates an unsaved draft. Save persists the draft asynchronously. Duplicate creates an independently identified copy. Delete confirms the selected profile's name before removing its saved metadata.

The driver selector switches between SQLite path/read-only controls and PostgreSQL host, port, database, user, TLS mode (verified identity or disabled), and root-certificate path. PostgreSQL defaults to verified TLS. A file picker assists path entry; typing a path does not trigger synchronous filesystem checks. PostgreSQL includes a masked Password field and “Save password in OS credential store” checkbox, initially unchecked for new profiles. Saved secrets are never loaded into the form: an existing credential reference checks the box and shows “Saved password — leave unchanged to keep”. Editing the field supplies an override, including an explicitly empty password. Save with the box checked replaces the secret when edited, or keeps an existing untouched secret. Unchecking schedules removal of its stored reference when Save succeeds; until then Test/Connect may still use the saved credential if no password override was entered. the typed session password remains available for Test or Connect. Successful remembered saves clear the field; failed saves retain the draft for retry. Test and Connect use a copy of the password and preserve the draft for subsequent Save or retry. Selecting another profile or successfully saving a remembered password clears the field. There is no plaintext storage fallback, and passwords never enter profile metadata. Cleanup warnings explicitly distinguish saved/deleted metadata from credential cleanup failure and remain visible after the list refresh.

Test validates the current unsaved form asynchronously. Connect submits the current form and reports the accepted session to the workspace, while keeping pending state and connection errors in the dialog. A selectable status line reports pending work and errors without modal success messages. While an operation is pending, the list, form, and operation buttons are disabled; Close remains available. Request tokens prevent unrelated responses from overwriting the form. Successful Save or Duplicate refreshes the list and selects the resulting profile. Initial loading never replaces an edited draft. Switching profiles or creating a new draft asks before discarding edits.
