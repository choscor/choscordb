## Page/schema memory reservations

The next continuation made concrete progress on §5.5/§9/§10. The core now acquires global and per-result reservations before schema/page work and stored-page reads. SQLite enforces the raw page limit before copying rows, dynamically defers wide payloads, and bounds schema allocations before execution/copy. Reservations travel with queued events and remain in the CXX lease arena until the native owner releases them. Qt pins its retained schema/page allocations, destroys replaced buffers before releasing the old lease, and shrinks transfer capacity only after CXX DTO destruction.

Default budgets remain 64MiB/result and 256MiB globally. The current conservative policy derives a raw-page ceiling from the effective result budget and reserves separate source/transfer headroom. A source quota leaves room for page transfers; completed SQLite cursors return unused source capacity using their retained-memory estimate. Configured memory limits currently require at least 1MiB. These are allocation reservations, not measured total process RSS; database-native working memory, documents/commands, deferred-value events, and the standalone hot cache are not a claim of complete global compliance.

## Shared hot-cache integration

The continuation connected the original-page LRU to the core's existing global/per-result memory broker. Every cached copy holds its own reservation, including its cache node and owned allocation capacities. Transfer capacity is reserved before cloning a cache hit. Pressure selects the result's own LRU when its limit binds, and otherwise the global LRU. A source-quota wait does not discard cached pages because doing so cannot free source capacity. The broker holds only a weak cache reference, avoiding an ownership cycle.

Visible Qt pages remain independently owned and pinned by their existing leases; evicting a raw hot copy cannot invalidate the displayed data. Misses read the original disk store without executing SQL again. Release/disconnect removes cached copies and releases their reservations. Diagnostics expose cache hits, misses, and resident bytes through the thin CXX/Qt adapter, without adding implementation controls to the product UI.

Behavioral tests prove cache hits by corrupting the backing page file after a successful fetch, then reading the unchanged cached value. Other tests cover LRU eviction and disk fallback, pressure while a consumer retains its page, cross-connection eviction, archived reads after cancellation, and release/disconnect cleanup. The native Previous-page test verifies an actual cache hit. Independent review found no actionable defect; a separate source-quota-only eviction regression was reproduced and fixed.

Full memory acceptance remains open for deferred-value events, large-value backing lifetime/chunking, and final allocation/performance measurements. PostgreSQL, profile/credential/history integration, exports in the desktop, and release gates remain unfinished.

## Original-result export integration

Export is now connected from the Qt dialog through CXX to the connection actor. The actor replays stored pages from ordinal zero and then advances the original cursor using the same fetch/persist/completion helpers as grid paging. It never re-executes SQL. An archived result whose remaining cursor was closed fails atomically instead of publishing a partial prefix. One generational export slot per connection bounds concurrent work; terminal events retire the slot. Cancellation, query release, connection shutdown, and cancellation of the original active query interrupt export waits and live fetching.

The streaming service writes all formats (CSV, JSON, JSON Lines, SQLite/PostgreSQL INSERT) cell by cell. Text/BLOB values can exceed resident memory budgets because deferred data is read and escaped in bounded chunks. UTF-8 sequences may span reads; malformed bytes fail without replacing the destination. Progress reports bytes during a large value, and rows only after completion. The shared export reservation remains alive in pending native/disk/chunk jobs even if their waiter is cancelled. Pending source operations settle before returning cursor/store ownership to the actor.

The nonmodal native dialog follows `docs/design/export.md`: format, destination, SQL identifier components, asynchronous destination checks, one overwrite confirmation, progress, Cancel, and inline errors. It disables conflicting workspace actions while exporting. Close requests cancellation; query replacement/disconnect invalidates pending checks and cancels the job. Existing files are replaced only after successful publication. Native tests exercise original-row export after browsing, overwrite cancellation, and destination failure while keeping the grid usable.

Independent code/spec reviews found and fixed stalled byte progress during a large value, excessive whole-row encoding allocation limits, and query cancellation not reaching a live export. Eight core regressions cover original-result continuation, UPDATE RETURNING without replay, roughly 6 MiB of deferred data under a 1 MiB result budget, cancellation/cleanup, incomplete archived results, release during memory waits, wide inline rows, and original-query cancellation.
